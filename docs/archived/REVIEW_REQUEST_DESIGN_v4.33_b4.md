# v4.33 설계 4판 검토 요청 (좁은 범위)

`docs/DESIGN_v4.33.md`가 4판으로 바뀌었습니다. 3판 검토 결과는 `docs/REVIEW_RESULT_b2.md`에 있습니다. 이번에는 **바뀐 부분만** 봐 주세요. 3판에서 '해결'로 판정한 항목과 바뀌지 않은 절은 다시 검토하지 않아도 됩니다.

구현 때 하나씩 바꿀 항목(G5~G8·G11, b2 3~5절)은 `docs/IMPL_CHECKLIST_v4.33.md`로 옮겼습니다. 이 항목들은 설계 문장이 아니라 구현과 시험으로 확인합니다.

**코드·노트북·시험·설계서는 고치지 마세요.** 결과는 `docs/REVIEW_RESULT_v4.33_b4.md`에 써 주세요. 새 발견은 H1부터 번호를 붙입니다. 대조할 코드는 v4.32.0입니다.

## 검토 질문

1. **G1~G4·G9·G10 반영:** 설계서 끝의 '검토 반영표'를 따라 항목마다 해결·부분 해결·미해결로 판정해 주세요. 근거가 되는 절은 아래와 같습니다.
   - G1: 실행기 규칙의 '권한 확인', '확인 필요' 처리의 '고를 수 있게 되는 조건'과 '선택 뒤 심판의 처리'
   - G2: 실행기 5단계와 단계 기록
   - G3: 심판 표, 신호 절
   - G4: 관리 일 절의 실행 ID와 인계, 취합 일 절, 재시작 인계
   - G9: 차례의 예외
   - G10: Keeper 깨우기 조건, 판정 루프 10단계, 신호 절 끝
2. **b2 4절 반영:** 확정 신청 식별, '모름' 전파, 부분 게시, 재시작 다시 발급, 확정 중 권한 상실, 요청 최종 상태가 4판 규칙으로 닫히는지 봐 주세요.
3. **권한 확인의 틈:** 권한 확인(읽기)과 CVAT 호출 사이에는 비교-쓰기 틈이 남습니다. 이 틈과 '15분 대기'가 합쳐져, 사람의 선택 뒤 옛 실행기의 쓰기가 새 일과 겹치는 경로가 남는지 봐 주세요. 남는다면 그 경로가 얼마나 좁은지(필요한 조건)도 적어 주세요.
4. **감시와 재시작 점검:** 새 절의 감시 표와 재시작 대조로, 핵심 기능(판정 루프, 마스터, 작업 프로세스, 실행기, 수집기, Keeper)이 멈추고 다시 시작할 때 사람이나 다른 기능이 알아채지 못하는 경우가 남는지 봐 주세요.
5. **점검표가 빠짐없는지:** `IMPL_CHECKLIST_v4.33.md`가 b2의 G5~G8·G11과 3~5절 내용을 빠뜨린 곳이 있는지만 봐 주세요. 점검표의 해결 방향 자체를 다시 검토하지는 않아도 됩니다.
6. **CTRL앱과 마스터 깨우기:** 'CTRL앱' 절과 '계정 역할'을 봐 주세요. Drive 소유 계정으로 하는 2차 권한 확인, 관리자 '보류 해제하고 깨우기', 일회용 코드(TOTP)를 신호 파일 생성 시각으로 검사하는 방식에 우회·재사용·잘못 거절하는 경로가 있는지 봐 주세요. Keeper가 Kaggle 키를 갖게 되면서 생기는 위험과, 지금 `Code.gs`의 GitHub 경로를 빼면 사라지는 기능이 있는지도 봐 주세요.
7. **새 위험:** 4판에서 새로 들어간 장치의 위험을 봐 주세요. 대상은 복구 자료 게시, 다시 발급, 신호 3단계, `submissions/`, 관리 일 실행 환경 지정(23번 Colab 전용), 받는 중 순서 예외, `people.json` 등록 규칙입니다.
