# 가지 앱 경합 통제 설계표 (v4.33 안)

2026-11-14 · 재웅님 (원본: Claude Docs 설계표, 이 파일은 그 사본)

여러 사람(M)이 여러 계정(U)과 여러 실행 세션(S)으로 동시에 일해도, 같은 요청·같은 TASK·같은 상태 파일을 두 곳이 쓰지 않게 하는 설계입니다. v4.32.0의 취합자 임대·소유 확인을 이 설계로 바꿉니다.

## 목적과 전제

원칙 네 가지:

1. **최소 단위 전담:** 요청 1건, TASK 1개, 앱 상태 전체 — 단위마다 쓰는 주체는 하나입니다.
2. **앞단 즉시, 뒤에서 확정:** 접수와 준비(받기·추론·track 만들기)는 바로 합니다. 확정(CVAT에 쓰기, TASK 기록, 요청 완료)은 허가가 있어야 합니다.
3. **지우지 않고 표시:** 파일을 지우는 대신 '지움' 표시를 남기고, 청소 셀이 나중에 정리합니다.
4. **심판 하나:** 배정·TASK 잠금·취합자는 Apps Script 심판(U1) 한 곳이 정합니다. 심판은 LockService로 한 번에 하나씩만 판정합니다.

전제:

- Google Drive에는 '읽은 내용이 그대로일 때만 쓰기'가 없습니다. 그래서 판정은 심판이 하고, 나머지는 판정 결과(세대 번호)를 따릅니다.
- Apps Script는 개인 gmail 계정입니다. 계정마다 시간 트리거 실행이 하루 90분입니다.
- 웹앱 배포 금지 약속 때문에 심판을 직접 부를 수 없습니다. 심판은 1분마다 돕니다.

## 식별자

공유 파일에 쓰는 모든 기록은 누가(M), 어느 실행에서(S), 어느 계정으로(U) 썼는지를 남깁니다.

| 기호 | 뜻 | 예 | 정해지는 곳 | 파일에 남기는 칸 |
| --- | --- | --- | --- | --- |
| M (작업자) | 앱을 쓰거나 셀을 실행하는 사람 | M1 재웅님, M2·M3 검토자·운영자 | `config/people.json` (사람 목록) | `by_m` |
| S (실행 세션) | 실제로 일하는 프로그램 하나 | Colab 30번 셀, Kaggle GPU 작업자, CPU 마스터, 사람이 직접 실행한 셀, ULD앱 실행 | 세션이 켜질 때 `SESSION_ID` | `session`, `s_kind`, `s_m` (그 세션을 켠 사람, GPU와 마스터는 `system`) |
| U (계정) | Apps Script가 도는 Google 계정, Drive 파일의 소유자 | U1 심판, U2 수집기, U3 알림 | 역할별로 고정 | `acct` |
| gen (세대) | 배정·잠금·임대가 바뀔 때마다 1씩 오르는 번호 | 배정 gen 3 | 심판 | `gen` |

- 사람이 Colab에서 셀을 실행하면 Drive에는 그 사람의 Google 계정으로 씁니다. Kaggle은 rclone 설정의 계정으로 씁니다. 그래서 같은 폴더에 여러 계정의 파일이 섞입니다.
- 생존 신호는 세션마다 따로 둡니다(`workers/<S>.json`). 지금처럼 자리(slot) 하나를 여러 사람의 Colab이 함께 쓰지 않게 합니다.

## 경합 순간과 최소 단위

경합이 생기는 순간은 열 가지이고, 최소 단위는 요청·TASK·앱 상태 세 가지로 모입니다.

| 번호 | 경합 순간 | 예 | 최소 단위 | 전담 | 정하는 곳 | 지금 지적 |
| --- | --- | --- | --- | --- | --- | --- |
| C1 | 요청 받기 | M2의 Colab과 GPU 작업자가 같은 요청을 집음 | 요청 1건 | 배정된 세션 S | 심판 | S1, F14 |
| C2 | 요청 상태 바꾸기 | settle·마스터·자동 동기화가 남의 요청을 완료로 | 요청 1건 | 배정된 세션 S | 심판(재배정) | S1, S2 |
| C3 | 배정기와 작업자 | 배정기가 요청 파일에 덧쓰는 사이 작업자가 받음 | 요청 1건 | 배정 내용은 `assign/`에만 | 심판 | 새로 찾음 |
| C4 | 앱의 취소와 작업자 | M1이 취소하는데 S는 진행 중 | 요청 1건 | 배정된 세션 S | 앱은 취소 표시만 | 새로 찾음 |
| C5 | 같은 TASK 작업 | M1의 track 중 M2가 5번 셀로 같은 TASK, ULD 교체 | TASK 1개 | TASK 잠금 보유 세션 | 심판 | F6 |
| C6 | TASK 기록·`tasks/<id>/` 쓰기 | 두 세션이 같은 TASK 기록을 고침 | TASK 1개 | C5와 같음 | 심판 | S5 |
| C7 | 앱 상태 파일 | 두 취합자, 넘겨받을 때 옛 사본 | 앱 상태 전체 | 취합자 | 심판(임대) | S3, S4 |
| C8 | 캐시(라벨 통계·수정량·스냅숏 목록) | 4번 셀이 통계 캐시를 덮음 | 앱 상태 전체 | 취합자 (아니면 세션 파일) | 심판(임대) | S6 |
| C9 | 세션 기록 합치기 | 합치며 다른 세션 파일을 지움 | 세션 파일 1개 | 청소 셀 | 사람 | F2 |
| C10 | 학습 폴더 `runs/<모델>` | 두 곳에서 같은 모델 학습 | 모델 1개 | 학습 잠금 보유 세션 | 지금 `RUNNING.json` 유지 | 해결됨 |

## 상태 정의

요청·TASK 잠금·취합자 임대는 각각 상태를 갖고, 상태를 바꾸는 주체가 정해져 있습니다. 굵은 글씨는 이번에 새로 생기는 상태입니다.

### 요청

| 상태 | 뜻 | 바꾸는 주체 | 앱에 보이는 말 |
| --- | --- | --- | --- |
| 접수됨 (pending) | 앱이 요청 파일을 만듦 | 앱 (M) | 접수됨 · 배정 대기 |
| **배정됨 (assigned)** | 심판이 세션 S와 TASK 잠금을 함께 정함 (`assign/` 파일에 S·gen) | 심판 (U1) | 배정됨 · M2의 Colab |
| 진행 중 (taken) | S가 배정을 확인하고 시작 | S | 진행 중 (TASK 3/5) |
| 받는 중 (waiting) | CVAT 백업·export를 기다림 | S | 받는 중 |
| **취소 요청됨** | 앱이 취소 표시 파일을 만듦 (요청 파일은 고치지 않음) | 앱 (M) | 취소 요청됨 |
| 완료 · 실패 · 취소됨 | 끝남 | S (배정 전 취소는 심판) | 완료 / 실패 / 취소됨 |
| **재배정** | S가 꺼져 심판이 다른 세션에 배정 (gen +1) | 심판 | 다시 배정됨 · 앞 세션 꺼짐 |

### TASK별 단계와 결과 (취소 경계)

요청 안의 TASK마다 지금 단계와 결과를 요청 파일의 `results`(TASK별 `step`·`status`)에 남겨, 작업자와 앱이 같은 최종 상태를 봅니다. 취소는 준비 단계면 지금 TASK도 바로, 확정 단계면 그 TASK를 마친 뒤 멈춥니다 (11/14 결정).

| 단계 | 구분 | 여기서 취소되면 | TASK 결과 |
| --- | --- | --- | --- |
| 1. 영상·백업 받기 | 준비 | 바로 멈춤 | 취소됨 (준비 중 멈춤) |
| 2. 추론·track 만들기 | 준비 | 바로 멈춤 (추론 중에도 프레임 몇백 장마다 확인) | 취소됨 (준비 중 멈춤) |
| 3. 올리기 전 라벨 백업 | 준비 | 바로 멈춤 (백업 파일은 남김) | 취소됨 (준비 중 멈춤) |
| 4. 기존 라벨 교체·새 라벨 올리기 | 확정 | 그 TASK를 끝까지 | 완료 |
| 5. 이름 바꾸기 (`_uld` → `_uld_AA`) | 확정 | 그 TASK를 끝까지 | 완료 |
| 6. TASK 기록 쓰기·잠금 반납 | 확정 | 그 TASK를 끝까지 | 완료 |
| 아직 시작 안 한 TASK | — | 하지 않음 | 취소됨 (시작 안 함) |
| 확정 단계 중 강제 중지(■)·세션 꺼짐 | — | 끝내지 못함 | 확인 필요 (라벨이 반만 바뀔 수 있음 → 올리기 전 백업과 비교) |

취소에 따른 요청 상태:

| 상태 | 뜻 | 바꾸는 주체 | 앱·작업자 화면에 보이는 말 |
| --- | --- | --- | --- |
| 취소 요청됨 | 앱이 취소 표시 파일을 만듦 | 앱 (M) | 취소 요청됨 |
| 멈추는 중 | S가 확정 단계의 TASK를 마무리 중 | S | 멈추는 중 · TASK 3 마무리 |
| 취소됨 | 멈춤 끝 | S (배정 전이면 심판) | 취소됨 (2/5 완료) |
| 확인 필요 | 확정 단계 중에 끊김 | S 또는 재배정된 세션 | 확인 필요 · TASK 3 |

요청 종류별 경계:

| 요청 | 멈추는 경계 | 남는 것 |
| --- | --- | --- |
| shape·track·자동 라벨 | 위 표의 확정 단계 전 | 완료된 TASK는 그대로 (되돌리려면 백업 복원을 따로) |
| 올리기 | TASK 단위 | 올린 TASK는 그대로 |
| 백업·export | CVAT에 이미 보낸 요청은 거둘 수 없음. 남은 TASK는 요청하지 않고 받기도 멈춤 | 받은 파일 |
| 학습 | 에폭 경계 | `last.pt` (이어서 학습 가능) |

- 작업자는 단계가 바뀔 때마다 취소 표시를 확인합니다. 사람이 직접 실행하는 셀도 같은 확인 지점을 둡니다.
- TASK별 `step`·`status`는 30번 셀 출력, 작업자 생존 신호(지금 하는 일), 앱 요청 탭에 같은 말로 보입니다.

### TASK 잠금 (`locks/TASK_<id>.json`, 새로 만듦)

| 상태 | 뜻 | 바꾸는 주체 |
| --- | --- | --- |
| **신청** | 세션이 신청 파일을 만듦 (`locks/ask/<S>__<id>.json`) | S |
| **허가** | 심판이 잠금을 S에게 줌 (gen +1) | 심판 |
| **사용 중** | S가 확정 단계를 함 (CVAT 쓰기, TASK 기록) | S (잠금 파일은 고치지 않음) |
| **반납 신청** | S가 끝났음을 표시 | S |
| **풀림** | 심판이 잠금을 풀고 다음 신청에 줌 | 심판 |
| **만료** | S의 생존 신호가 3분 끊김 → 심판이 회수 | 심판 |

### 취합자 임대 (`jobs/STATE_OWNER.json`)

| 상태 | 뜻 | 바꾸는 주체 |
| --- | --- | --- |
| 비어 있음 | 취합자 없음 | 심판 |
| **인계 중** | 심판이 새 세대로 주었고, 새 취합자가 최신 tracked·상태를 받는 중 | 심판 → 취합자 |
| **취합 중** | 받기를 마치고 쓰기 시작 | 취합자 |
| 내려놓음 · 만료 | 꺼지거나 더 높은 순위가 나타남 | 심판 |

- 취합자도 심판이 정합니다. 작업자는 자기 생존 신호에 '취합 가능, 순위 3/2'만 적습니다. v4.32.0처럼 작업자가 스스로 임대를 쓰지 않습니다.

### 지움 표시

| 파일 종류 | 표시 방법 | 읽는 쪽 |
| --- | --- | --- |
| JSON (요청·잠금·표시 파일) | 내용에 `deleted: {at, by_m, session, why}` | 표시된 파일은 없는 것으로 봄 |
| 그 밖 (CSV·zip·XML) | 이름 끝에 `.deleted` (이름 바꾸기) | `.deleted` 파일은 읽지 않음 |

## 공유 파일별 쓰는 주체

파일마다 만드는 곳과 그다음에 쓰는 곳이 하나씩입니다. 다른 곳이 바꾸고 싶으면 자기 파일에 표시를 남기고, 주인이 반영합니다.

| 파일 | 만드는 곳 | 그다음 쓰는 곳 (하나) | 다른 곳이 바꾸고 싶을 때 | 지울 때 |
| --- | --- | --- | --- | --- |
| `requests/REQ_*`, `relabel/requests/REQ_*` | 앱 (M), 수집기 (U2, 자동 백업·export) | 배정된 세션 S. 상태가 바뀔 때 파일 이름은 이름 바꾸기로 (새로 쓰고 옛것 지우기 아님) | 취소: 앱이 `requests/cancel/<id>.json` · 받는 중 정리: S만 | 끝난 지 30일 뒤 청소 셀이 보관 폴더로 |
| `requests/assign/ASSIGN_*` | 심판 (U1) | 심판만 (S·gen·잠금 TASK) | 없음 | 표시 |
| `requests/cancel/*` (새로) | 앱 (M) | 없음 (만들기만) | — | 처리 끝나면 S가 표시 |
| `locks/TASK_<id>.json` (새로) | 심판 | 심판만 | 세션은 `locks/ask/`에 신청·반납 | 표시 |
| `locks/ask/<S>__<id>.json` (새로) | 세션 S | S만 | — | 심판이 처리하면 S가 표시 |
| `jobs/STATE_OWNER.json` | 심판 | 심판만 (세대) | 작업자는 생존 신호에 '취합 가능' | — |
| `web/state.json`, `relabel/state.json`, `relabel/tracked.json` | 취합자 | 취합자만 (쓰기 직전 세대 확인, 파일에 gen) | `jobs/DIRTY_<S>.json` 표시 · 숨기기는 요청으로 | — |
| `web/label_stats.json`, `web/corrections.json`, 스냅숏 목록 | 취합자 | 취합자만 | 세션 파일 `web/stats/<S>.json` (취합자가 합침) | 합친 뒤 취합자가 표시 |
| `relabel/tasks/<id>.json`, `tasks/<id>/**`, `relabel/previews/<id>*` | TASK 잠금 보유 세션 | 그 세션만 | 잠금 없으면 읽기만 | — |
| `workers/<S>.json` (새로, 생존 신호) | 세션 S | S만 | — | 꺼진 지 1일 뒤 청소 셀 |
| `jobs/DIRTY_<S>.json`, `jobs/DONE_<S>.json` | 세션 S | S만 | 취합자는 처리한 번호를 자기 상태 파일에 기록 | 청소 셀 |
| 세션 기록 `logs/shards/<이름>/<S>.csv` | 세션 S | S만 | — | 합치기는 청소 셀 (합친 파일 새로, 원본은 `.deleted`) |
| `backup_status.csv`, 작업보드 | 백업을 실행한 세션 | 예외: 파생 파일 (세션 기록에서 다시 만듦) | — | — |
| `status/cvat_tasks.json` | 수집기 (U2) | 수집기만 | — | — |
| `runs/<모델>/**` | 학습 잠금 보유 세션 | 그 세션만 (`RUNNING.json`) | — | 29번 셀 (모델 정리) |
| `config/test_tasks.json` | 사람 (33번 셀) | 사람만, 파일에 gen | — | — |
| `CVAT_UpLoader/**` | ULD앱 | ULD앱만 (우리는 읽기만) | — | — |

- 새 파일을 만드는 것은 경합이 아닙니다. 이름에 세션이나 번호가 들어가 같은 이름이 생기지 않기 때문입니다.
- 배정기는 지금 요청 파일에 `assigned_to`를 덧씁니다(C3). 이것을 멈추고 `assign/` 파일에만 씁니다.

## 장면별 흐름

사람은 항상 바로 반응을 보고, 심판의 확정은 준비 단계가 도는 동안 1분 안에 도착합니다.

| 장면 | 누가 (M · S · U) | 앞단: 바로 보이는 것 | 뒤에서 확정 | 결과 |
| --- | --- | --- | --- | --- |
| 1. 앱에서 track 요청 | M1, AA앱 | '접수됨 · 배정 대기' | U1 심판이 1분 안에 세션 S(예: M2의 Colab)와 TASK 101 잠금을 함께 정함 | '배정됨 · M2의 Colab' → S가 '진행 중' → '완료', 잠금 반납. 지금도 배정을 기다리므로 새 대기 없음 |

## 계정 역할 분담

심판은 U1 한 계정·한 프로젝트에만 둡니다. 나머지 일을 U2·U3으로 나눠 계정마다 하루 90분 한도를 따로 씁니다.

| 계정 | 프로젝트 | 하는 일 | 쓰는 파일 | CVAT 토큰 | 주기 |
| --- | --- | --- | --- | --- | --- |
| U1 | 심판 (`Arbiter.gs`) | 요청 배정, TASK 잠금 허가·회수, 취합자 임대, 꺼진 세션 것 재배정, 배정 전 취소, 야간 승인 | `requests/assign/*`, `locks/TASK_*`, `jobs/STATE_OWNER.json`, `jobs/ARBITER.json`(심판 생존 신호) | 없음 | 1분 |
| U2 | 수집기 (`Collector.gs` + `Uld.gs`) | CVAT 목록 수집, 사라진 TASK 표시, `_uld` 백업·`vf` export 자동 요청 만들기, ULD 연결 | `status/*`, 새 요청 파일 | 있음 (이 프로젝트에만) | 10분 |
| U3 | 알림 (`Notify.gs`) | CPU 마스터 깨우기·정지, 메일 알림, 심판이 멈추면 알림 | `jobs/STOP_*`, 메일 | 없음 | 5분 |

- **심판은 가볍게:** 1분 주기 한 번이 3.75초를 넘으면 하루 90분을 다 씁니다(1,440회). 바뀐 것이 없으면 폴더 목록만 보고 끝내고, 더 무거운 일(보고·메일)은 U3으로 보냅니다.
- **공유 권한:** U1·U2·U3, 각 사람(M)의 Google 계정, Kaggle rclone 계정이 모두 `eggplant_yolo` 폴더의 편집자여야 합니다. `CVAT_UpLoader`는 U1·U2에게 읽기, ULD앱 계정에게 편집.
- **심판이 멈추면:** 한도 초과 등으로 심판이 멈추면 새 배정·허가만 멈춥니다. 이미 허가받은 일은 계속되고, 앱은 `jobs/ARBITER.json`을 보고 '배정기 멈춤 n분'을 보여 줍니다.

## 지움 표시와 청소 셀

앱·심판·작업자는 파일을 지우지 않습니다. 표시만 하고, 새 청소 셀(34번)을 사람이 실행해 정리합니다.

지금 지우는 곳과 바꿀 방법:

| 지금 지우는 것 | 누가 | 바꿀 방법 |
| --- | --- | --- |
| 상태가 바뀐 요청의 옛 이름 파일 | 작업자·마스터 (Kaggle) | 이름 바꾸기 하나로 (새로 쓰고 지우지 않음) |
| `jobs/DIRTY_*`, `DONE_*` | 취합자 | 취합자는 처리한 표시를 자기 상태 파일에 기록, 파일은 남김 |
| 합친 세션 기록 | 28번 셀·마스터 | 청소 셀로 옮김, 원본은 `.deleted` |
| `jobs/STOP_*` | 마스터·앱 | 내용에 `deleted` 표시 |
| 임시 파일 | 각 세션 | 세션 임시 폴더에만 두고 Drive에 올리지 않음 |

청소 셀(34번) 동작:

1. 표시된 파일과 오래된 기록을 찾아 목록을 보여 줍니다 (미리 보기).
2. 표시 뒤 7일(`CLEAN_DAYS`)이 지난 것만, `CONFIRM = True`일 때 실제로 지웁니다.
3. 끝난 지 30일 지난 요청은 지우지 않고 `requests/archive/`로 옮깁니다.
4. 소유자가 달라 못 지운 파일은 '계정별 목록'으로 보여 줍니다. 그 계정의 Apps Script가 자기 소유 파일만 지우는 청소 함수(수동 실행)를 둡니다.
5. 지금 일하는 세션이 있거나 심판이 잠금을 주고 있는 TASK의 파일은 건드리지 않습니다.

절대 지우지 않는 것: `CVAT_UpLoader/`, `videos/`, `backups/`, `exports/`의 zip, 학습 가중치(모델 정리는 29번 셀 몫), CVAT TASK.

## 실패·만료·인계 규칙

모든 쓰기는 쓰기 직전에 자기 세대(gen)를 다시 확인하고, 쓴 파일에 그 세대를 함께 적습니다.

| 규칙 | 내용 | 막는 지적 |
| --- | --- | --- |
| 세대 확인 | 배정·잠금·임대 파일을 쓰기 직전에 다시 읽음 (기억해 둔 값 쓰지 않음). 세션·세대가 내 것이 아니면 쓰지 않음 | S4 |
| 세대로 가려내기 | 읽는 쪽(취합자·심판)은 옛 세대가 쓴 기록을 버리고 다음 차례에 바로잡음. 다시 읽기와 쓰기 사이 몇 초의 틈을 이것으로 닫음 | S4, F14 |
| 만료 | 세션의 생존 신호(`workers/<S>.json`)가 3분 끊기면 심판이 그 세션의 배정·잠금·임대를 회수하고 gen +1. 오래 걸리는 일은 생존 신호가 계속 뛰므로 만료되지 않음 | S2, F9 |
| 인계 중 | 새 보유자는 최신 자료(tracked·상태, 앞 세션이 못 올린 기록)를 받아야 '사용 중'. 받지 못하면 쓰지 않고 다음 차례에 다시 | S3 |
| 못 올린 TASK 기록 | 메모리가 아니라 `outbox/<S>/<id>_<번호>.json`에 남김. 남은 것이 있으면 그 TASK 잠금을 반납하지 않고, 요청은 '완료(기록 미반영)'. 다음 보유자가 인계 중에 먼저 반영 | S5 |
| 취소 | 앱은 취소 표시 파일만. 배정 전이면 심판이, 진행 중이면 S가 준비 단계에서는 바로, 확정 단계에서는 그 TASK를 마치고 멈춤 → '취소됨 (n/m 완료)'. 확정 중에 끊기면 '확인 필요' | C4 |
| 받는 중 정리 (settle) | 배정된 S만 함. 받기는 여러 세션이 해도 되지만 요청 상태는 S만 바꿈 | S2 |
| 심판 멈춤 | 새 배정·허가만 멈춤. 앱에 '배정기 멈춤 n분', U3이 메일 | — |

- 사람이 직접 실행하는 셀도 같은 규칙을 따릅니다. `FROM_REQUESTS`로 요청을 받을 때는 내 세션에 배정된 것만 받고, 확정 단계 전에 TASK 잠금을 확인합니다 (S1).

## ULD앱 연동

ULD앱은 교체(옛 TASK를 없애고 새로 올림) 한 순간만 우리 앱과 겹치므로, 그 순간에만 TASK 잠금을 받습니다.

| ULD앱이 하는 일 | 우리 앱과 겹침 | 방법 |
| --- | --- | --- |
| 새 TASK 만들기 | 없음 (새 번호) | 지금 그대로 |
| 중복 검사 | 읽기만 | 이름이 아니라 TASK 번호로 찾음 (우리 앱이 `_uld` → `_uld_AA`로 바꾸므로) |
| 교체 | **겹침** — 우리 세션이 그 TASK에 track·올리기·백업 중일 수 있음 | ULD가 교체 신청을 자기 폴더(`CVAT_UpLoader/requests`)에 씀 → 심판(U1, 읽기만)이 그 TASK 잠금을 ULD 세션에 허가 → ULD가 `locks/TASK_<id>.json`을 읽고 교체 → 반납 신청 |
| 올린 뒤 수집기 연결 (`uldAfterCollect_`) | 수집기 안 | U2 수집기에 그대로 둠 |

- ULD앱 화면에는 '교체 대기 · TASK 101은 M2의 Colab이 track 중 (14:05부터)'처럼 잠금 보유자를 보여 줍니다.
- 우리 앱은 지금처럼 `CVAT_UpLoader/`를 읽기만 합니다. ULD앱은 우리 폴더의 `locks/`와 요청 상태를 읽기만 합니다.
- 교체된 옛 TASK는 수집기가 'CVAT에서 사라짐'으로 표시하고, ULD 기록(`replace`)으로 새 TASK와 잇습니다 (지금 방식).

## 정할 것과 먼저 시험할 것

코드를 고치기 전에 시험 두 개와 결정 다섯 개가 필요합니다.

먼저 시험할 것:

- [ ] 공유 폴더 권한 시험: U1이 만든 파일을 다른 계정(M의 Google 계정, Kaggle rclone 계정)이 ① 이름 바꾸기 ② 내용 덮어쓰기 ③ 지우기 할 수 있는지

정할 것 (괄호 안은 제안):

1. 사람 목록: M1~M3의 이름과 앱에서 쓰는 이름 (`config/people.json`에 이름·역할).
2. 사람이 직접 실행한 셀이 확정 단계에서 허가를 기다리는 시간 (2분, 그 뒤에는 보관).

이 설계를 적용하면 S1~S6과 2차-2의 F6·F9가 함께 다뤄집니다. F2는 청소 셀로, F7(요청별 CVAT 범위)·F8(GPU 줄 예약)은 따로 남습니다.
