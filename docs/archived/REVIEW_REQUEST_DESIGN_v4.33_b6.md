# v4.33 설계 6판 검토 요청 — 구현 착수 전 확인

`docs/DESIGN_v4.33.md`가 6판으로 바뀌었습니다. 5판 네 관점 검토 결과(J1~J10)는 `docs/REVIEW_RESULT_v4.33_b5.md`에 있습니다. 구현 점검표 `docs/IMPL_CHECKLIST_v4.33.md`도 보충했습니다. 그 전 검토는 `REVIEW_RESULT_b1.md`·`REVIEW_RESULT_b2.md`·`REVIEW_RESULT_v4.33_b4.md`입니다 (`docs/` 또는 `archived/`).

이번 검토의 목적은 **구현을 시작해도 되는지 판단**하는 것입니다. 6판에서 바뀐 부분을 중심으로, 동시성 제어·작업 스케줄링·장애 복구·접근 제어 네 관점에서 봐 주세요.

**코드·노트북·시험·설계서는 고치지 마세요.** 결과는 `docs/REVIEW_RESULT_v4.33_b6.md`에 써 주세요. 새 발견은 K1부터 번호를 붙이고, 관점(동시성·스케줄링·복구·접근)을 적어 주세요. 대조할 코드는 v4.32.0입니다.

## 1. J1~J10 반영 판정

설계서 끝의 '검토 반영표'를 따라 J1~J10을 해결·부분 해결·미해결로 판정해 주세요.

## 2. 6판에서 새로 들어간 장치

아래 장치마다 네 관점에서 새 위험이 있는지 봐 주세요.

1. **버전과 채택** ('학습 줄과 관리 일' 절): 버전 경로, 버전 목록 파일(`_files.json`), 심판만 쓰는 `CURRENT.json`, 채택 조건(decision·gen·실행 ID), 읽는 쪽 전환, 옛 산출물의 `v/legacy/` 등록, 청소의 지움 조건.
2. **학습 줄 분리:** 모델별 학습 잠금, 시작 버전 고정, '채택 대기'. 학습과 관리 일이 서로 기다리지 않게 되면서 생기는 경합이 있는지 봐 주세요. 예: 학습 중 23번 복원·FORCE_NEW·33번 시험 설정 변경·청소.
3. **관리 일 '실행기 대기' 비켜 두기:** 차례가 바뀌어 생기는 문제가 있는지 봐 주세요.
4. **신호를 지금 상태에서 다시 판정** ('신호' 절): 처리기를 지금 상태에 대한 함수로 두고, 새 파일은 없을 때만, 상태 전이는 gen이 같을 때만, 재시작 때 다시 발급 뒤 실행. J4 반례가 닫히는지, 새로 놓치는 효과(처리돼야 하는데 '이미 진행됨'으로 건너뛰는 경우)가 있는지 봐 주세요.
5. **신뢰 모델과 신원 확인:** '신뢰 모델' 절과 심판 2단계의 소유 계정 확인. 앱·수집기·rclone처럼 파일을 대신 만드는 경우의 소유 계정 연결이 맞는지 봐 주세요.
6. **실행 코드의 신뢰 경계:** `deploy/` 배포 목록과 검증 사슬(Keeper 해시 → 노트북 안 목록 해시 → 파일 해시). 검증을 거치지 않고 실행되는 코드 경로가 v4.32.0 로딩 방식에 남는지 봐 주세요.
7. **새 TASK 만들기, Keeper 시도 ID, 깨우기 조건, 받는 중 요청별 파일, 청소 보존 조건.**
