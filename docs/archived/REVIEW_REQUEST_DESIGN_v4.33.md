# v4.33 설계 7판 검토 요청 (좁은 범위)

`docs/DESIGN_v4.33.md`가 7판으로 바뀌었습니다. 6판 검토 결과(K1~K6)는 `docs/REVIEW_RESULT_v4.33_b6.md`에 있습니다. 구현 점검표 `docs/IMPL_CHECKLIST_v4.33.md`도 보충했습니다.

이번 검토는 **바뀐 부분만** 봐 주세요. 구현 1단계(판정 함수·가짜 환경 시험)는 이 검토와 나란히 시작합니다. 여기서 나온 지적은 구현에 반영합니다.

**코드·노트북·시험·설계서는 고치지 마세요.** 결과는 `docs/REVIEW_RESULT_v4.33_b7.md`에 써 주세요. 새 발견은 L1부터 번호를 붙이고 관점(동시성·스케줄링·복구·접근)을 적어 주세요. 대조할 코드는 v4.32.0입니다.

## 검토 질문

1. **K1~K6 반영:** 설계서 끝의 '검토 반영표'를 따라 해결·부분 해결·미해결로 판정해 주세요.
   - K1: '신호' 절의 효과별 완료 증거 표와 '취소는 요청에 붙는 표시'. b6의 반례(취소 계획 gen3 → 재배정 gen4)와 '잠금만 반영 뒤 종료'가 닫히는지.
   - K2: '실행 코드의 신뢰 경계'의 한 방향 사슬과 배포 순서로 정상 배포가 만들어지고, 검증 없이 실행되는 경로가 없는지.
   - K3: 새 절 '계정과 신원'의 계정 지도, 계정별 허용 입력, 접수 기록.
   - K4: `next_wake_at`, `observed_from`, 새 실행기 등장.
   - K5: '학습 줄'의 학습 중 설정 변경 (결정 가).
   - K6: '새 TASK 만들기'의 같은 이름 하나씩, 빈 TASK 먼저, 후보 검증.
2. **계정 사실과의 일치:** 실제 운영은 이렇습니다.
   - A0(재웅님): 공유 폴더 소유자, 앱, Colab, Kaggle 보조 실행기.
   - K(동료 명의): Kaggle 마스터·작업 프로세스·GPU 작업자. `RCLONE_CONF`는 K 인증.
   - G(동료 명의): Apps Script 수집기·Keeper.
   - CVAT 계정은 하나입니다.
   
   이 조건에서 '계정과 신원' 절의 신뢰 규칙(판정 파일은 K만, 자격은 G만, 요청자는 접수 기록)이 우회되거나 정상 입력을 잘못 거절하는 경로가 있는지 봐 주세요. 관리자 전용 폴더(`eggplant_admin/`, 공유 폴더 밖)도 포함합니다.
3. **새로 생긴 위험:** 7판에서 새로 들어간 규칙의 위험을 봐 주세요. 대상은 접수 기록, 효과별 완료 증거, `locks/create/`, A0 Kaggle 보조 실행기, '알려진 한계'에 추가한 세 항목입니다.
