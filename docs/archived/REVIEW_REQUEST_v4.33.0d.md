### B. 저장소 어댑터·마스터 루프

3. **'모름' 전달:** `arb_io.snapshot`이 못 읽은 것을 빠짐없이 '모름'으로 넘기는지 봐 주세요. 대상은 목록 실패, 파일 읽기 실패, JSON 해석 실패, 시간 초과, 캐시입니다. '없음'으로 잘못 넘어가는 경로를 찾아 주세요.
4. **쓰기:** `apply_writes`가 실패 지점에서 멈출 때 다음 회차가 수렴하는지 봐 주세요. `RcloneStore.write_json`의 '없을 때만 만들기'(확인 뒤 쓰기)에 남는 틈이 단일 작성자 원칙 안에서 받아들일 만한지도 봐 주세요.
5. **rclone 명령:** `lsjson` 필터와 메타데이터(`owner`·`btime`) 해석이 실제 rclone 동작과 맞는지 봐 주세요. 실측은 범위 밖이므로 문서·코드 기준으로 의심되는 곳만 짚어 주세요.

### C. 실행기 뼈대

6. **심판과의 약속:** `executor.py`가 설계 '실행기 규칙'과 '보고·결과·인계 계약'을 지키는지 봐 주세요.
   - 식별 묶음을 빠짐없이 채우는지
   - 다시 발급 뒤 다시 보고하는지
   - 단계별 권한 확인을 거치는지
   - 취소·멈춤 경계가 맞는지
   - 권한을 잃으면 복원하지 않는지
7. **핸들러 경계:** 핸들러가 `ctx.auth()`를 거치지 않고 CVAT에 쓰는 것은 이 뼈대가 막지 못합니다. 2단계에서 `access.CvatFactory`와 함께 쓰는 것이 전제입니다. 이 전제 말고, 뼈대 자체가 잘못된 순서로 핸들러를 부르는 경우가 있는지 봐 주세요. 예: 승인 전 commit, 같은 TASK를 두 번 commit, 실패 뒤 다시 commit.
8. **실행기 재시작:** 실행기 프로세스가 죽고 새 세션으로 뜨는 경우, 옛 세션의 배정·잠금이 설계대로 정리되는지 봐 주세요(승인 전 회수, 승인 뒤 '확인 필요').

### D. Keeper

9. `keeperDecide_`가 설계 '계정 역할'·'CTRL앱'의 규칙과 일치하는지 봐 주세요. 대상은 자격, 정지 보류 판정, 2차 권한 확인, 밤 규칙, 중간 장애 뒤 재시도입니다. 반례를 찾아 주세요.
