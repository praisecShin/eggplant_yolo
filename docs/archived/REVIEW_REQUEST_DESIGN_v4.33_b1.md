# v4.33 설계 2판 검토 요청

`docs/DESIGN_v4.33.md`가 2판으로 바뀌었습니다. 1판 검토(D1~D14)와 11/14 결정을 반영했습니다. 11/14 결정은 심판을 CPU 마스터로 옮기고 Apps Script는 심판 자격만 주는 것, 그리고 차례 묶음을 5개 TASK로 하는 것입니다.

**코드·노트북·시험은 고치지 마세요.** 결과는 `REVIEW_RESULT.md`에 써 주세요. 새 발견은 E1부터 번호를 붙이고, 형식은 지난 검토와 같습니다. 대조할 코드는 v4.32.0입니다.

## 검토 질문

1. **1판 지적 반영:** 설계서 끝의 '1판 검토 반영표'를 따라 D1~D14가 해결됐는지 항목마다 판정해 주세요. 판정은 해결, 부분 해결, 미해결 셋 중 하나입니다.
2. **심판 줄 구성:** CPU 마스터의 네 줄 구성을 지금 `kaggle_cpu_master.py`와 대조해 주세요. 네 줄은 심판, 작업, 취합, 생존 신호입니다.
   - 줄끼리 같은 파일을 쓰거나 같은 로컬 경로를 덮는 곳이 남는지 봐 주세요.
   - 심판 한 회 순서 1~7에 빠진 단계나 순서 문제가 있는지 봐 주세요.
3. **심판 자격:** Apps Script(U2)가 LockService로 자격을 주고 마스터가 자격 gen을 매 회 확인하는 방식으로, 심판이 둘이 되는 경로가 막히는지 봐 주세요. 마스터 재시작, 새 버전 올리기, Drive 지연이 겹치는 경우를 포함합니다.
4. **격리와 확인:** 확정 중 끊긴 TASK를 회수하지 않고 격리한 뒤 '확인' 일로 다시 배정하는 흐름에 빈틈이 있는지 봐 주세요.
   - 앞 세션의 늦은 CVAT 작업과 다시 겹칠 수 있는지 봐 주세요. 10분 이상 지난 뒤 확인하도록 되어 있습니다.
   - 확인 결과를 정하는 기준이 지금 백업·복원 코드로 구현 가능한지 봐 주세요.
5. **확정 경계 표:** '확정 경계: 일 종류별' 표를 지금 셀·scripts 코드 순서와 맞춰 봐 주세요. 준비로 분류했는데 실제로 CVAT나 공유 Drive를 바꾸는 곳이 남았는지 확인해 주세요. 특히 `auto_annotate_frames`를 로컬 완성과 올리기로 나눌 때 깨질 기존 동작(사람 라벨 보호, 복원, 기록)도 짚어 주세요.
6. **새로 생긴 위험:** 2판에서 새로 들어간 장치에서 생기는 경합·한도·운영 위험을 봐 주세요. 대상은 자원 대기열, 묶음 차례 넘김, outbox ①~⑤, 신호와 ack, 운영 전환의 최소 버전, 데이터셋 버전 고정입니다.
