# v4.33 설계 3판 검토 요청

`docs/DESIGN_v4.33.md`가 3판으로 바뀌었습니다. 2판 검토(E1~E14)를 받고 설계를 **단순화**했습니다. 2판 검토 결과는 `docs/REVIEW_RESULT_b1.md`에 있습니다.

단순화의 핵심은 넷입니다.
- 사람은 CVAT에 직접 올리지 않습니다. 사람이 실행하는 셀은 분석 모드입니다.
- 바꾸는 일은 배정받은 실행기만 합니다.
- 마스터는 판정 루프와 별도 작업 프로세스로 나뉩니다.
- 자동 복구 대신 '확인 필요'로 사람에게 넘깁니다. 모델·데이터셋 일은 관리 일로 묶어 전체에서 하나만 실행합니다.

**코드·노트북·시험은 고치지 마세요.** 결과는 `REVIEW_RESULT.md`에 써 주세요. 새 발견은 G1부터 번호를 붙입니다. 대조할 코드는 v4.32.0입니다.

## 검토 질문

1. **E1~E14 반영:** 설계서 끝의 '검토 반영표'를 따라 항목마다 판정해 주세요. 판정은 해결, 부분 해결, 미해결 셋 중 하나입니다.
2. **분석 모드가 막히는가:** '셀 분류'와 '분석 모드를 지키는 장치'로 사람 실행 셀이 CVAT나 공유 파일을 바꾸는 경로가 실제로 막히는지 봐 주세요. 장치는 CVAT 읽기 전용 감싸기와 쓰기 경로 확인입니다.
   - 0~33번 셀과 scripts 안에서 감싸기를 거치지 않고 CVAT를 바꾸는 호출이 있는지 찾아 주세요. 직접 `requests`, `cvat_sdk` 하위 API, 백업 스크립트의 자체 세션이 대상입니다.
   - 쓰기 경로 확인을 거치지 않는 쓰기가 있는지 찾아 주세요. `open(..., 'w')`, `to_csv`, `shutil`, 0번 셀 자동 동기화가 대상입니다.
3. **확정 신청·승인 흐름:** 실행기 규칙 1~8단계와 판정 루프 한 회 1~8의 순서로, 같은 TASK를 두 실행기가 동시에 확정할 수 있는 경로가 남는지 봐 주세요. 재시작, epoch 교체, '모름' 처리를 포함합니다.
4. **작업 프로세스 분리:** 마스터 판정 루프와 CPU 작업 프로세스를 나눌 때, 지금 `kaggle_cpu_master.py`의 기능이 빠지거나 두 곳이 같은 파일을 쓰게 되는 곳이 있는지 봐 주세요. 대상 기능은 백업, export, 받는 중 확인, 취합, GPU 깨우기, 정지 처리입니다.
5. **단순화로 잃는 것:** 단순화 때문에 지금 되던 기능이 안 되거나 크게 느려지는 곳을 짚어 주세요. 예시는 아래 셋입니다.
   - 관리 일을 하나만 실행해서 생기는 대기
   - 마스터가 꺼져 있을 때 상태 갱신이 멈추는 것
   - 분석 모드라서 막히는 지금의 사람 작업 흐름
6. **새 위험:** 3판에서 새로 들어간 장치의 위험을 봐 주세요. 대상은 '이 결과 올리기', 확인 필요 화면의 세 선택지, 신호 장부, Keeper의 깨우기 조건, 스냅숏 목록 분리입니다.
