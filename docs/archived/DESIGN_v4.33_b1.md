# 가지 앱 경합 통제 설계표 2판 (v4.33)

2026-11-14 · 재웅님 · 1판 검토(D1~D14)와 11/14 결정(심판 = CPU 마스터, 차례 묶음 5개)을 반영

여러 사람(M)이 여러 계정(U)과 여러 실행 세션(S)으로 동시에 일해도, 같은 요청·같은 자원·같은 상태 파일을 두 곳이 쓰지 않게 하는 설계입니다. 판정은 CPU 마스터 안의 심판 줄 한 곳이 내리고, 쓰는 쪽은 판정 결과(세대 번호)를 따릅니다.

## 목적과 전제

원칙 다섯 가지:

1. **최소 단위 전담:** 요청 1건, 자원 1개(TASK·모델·데이터셋·설정), 앱 상태 전체 — 단위마다 쓰는 주체는 하나입니다.
2. **앞단 즉시, 뒤에서 확정:** 접수와 준비는 바로 합니다. 준비 산출물은 세션 임시 폴더에 둡니다. 확정(CVAT에 쓰기, 공유 폴더에 게시, TASK 기록, 요청 완료)은 허가가 있어야 합니다.
3. **지우지 않고 표시:** 파일을 지우는 대신 '지움' 표시를 남기고, 청소 셀이 정리합니다.
4. **심판 하나:** 배정·자원 잠금·취합자는 CPU 마스터의 심판 줄 한 곳이 정합니다. 심판이 둘이 되지 않게 Apps Script가 심판 자격을 하나만 줍니다.
5. **세대는 Drive만 지킨다:** 세대 번호는 Drive 파일 쓰기를 막을 수 있지만, 이미 보낸 CVAT 작업은 막지 못합니다. 그래서 CVAT 확정 중에 끊긴 자원은 회수하지 않고 격리합니다.

전제:

- Google Drive에는 '읽은 내용이 그대로일 때만 쓰기'가 없습니다. 판정은 심판이 하고, 다시 읽기와 쓰기 사이 몇 초의 틈은 세대로 가려냅니다.
- 웹앱 배포 금지 약속 때문에 심판을 직접 부를 수 없습니다. 작업자는 파일로 신청하고, 심판은 20~30초마다 판정합니다.
- 지금 Apps Script 배정기는 5분마다 돕니다(`DISPATCH_MIN=5`). 2판에서는 배정을 심판 줄이 하므로 앱 요청의 배정 대기가 5분에서 20~30초로 줄어듭니다.
- CPU 마스터는 꺼져 있을 수 있습니다(밤, 세션 시간 한도). 꺼져 있을 때 할 일이 생기면 Apps Script가 깨우고, 켜지는 몇 분 동안 앱에는 '배정기 켜는 중'이 보입니다.

## 심판: CPU 마스터의 줄 구성

CPU 마스터는 한 프로세스 안에서 네 줄로 나뉘어 동시에 돕니다. 줄끼리는 쓰는 파일이 겹치지 않고, 로컬 임시 폴더도 줄마다 따로 씁니다.

| 줄 | 하는 일 | 쓰는 파일 | 규칙 |
| --- | --- | --- | --- |
| 심판 줄 | 20~30초마다 판정 (아래 순서) | `requests/assign/*`, `locks/*`, `jobs/STATE_OWNER.json`, `jobs/ARBITER.json` | CVAT를 부르지 않음. 한 회 시간 한도 20초. 바뀐 파일만 읽음 |
| 작업 줄 (1~2) | 마스터에 배정된 백업·export·AA 작업·받는 중 확인 | 자기 요청, 잠금 받은 자원 | 다른 작업자와 같은 규칙 (신청·허가·확정) |
| 취합 줄 | 상태 갱신, 기록 합치기, `sim/**` 합치기 | 상태 파일·캐시 | 취합자 임대가 있을 때만. 표시가 생기거나 15분마다 |
| 생존 신호 줄 | 60초마다 생존 신호 | `workers/<마스터>.json` | 지금과 같음 |

심판 한 회의 순서:

1. 바뀐 파일 찾기: 요청 폴더 2개, `locks/ask/`, `workers/`, `jobs/signals/`, `CVAT_UpLoader/requests`의 목록을 수정 시각과 함께 받아(`lsf`), 지난 회와 달라진 파일만 읽습니다. 10분마다 한 번은 전체를 다시 읽습니다.
2. 만료: 생존 신호가 3분 끊긴 세션의 배정·잠금을 정리합니다. 확정 중이던 자원은 회수하지 않고 격리합니다(아래 실패 규칙).
3. 취소: 배정 전 요청은 바로 종료 판정을 `assign/`에 적습니다. 진행 중 요청은 그 세션에 맡깁니다.
4. 대기열: 자원마다 대기열을 접수 순서로 정합니다(차례와 순서 절).
5. 허가: 묶음 단위로 배정·잠금을 주고 gen을 올립니다.
6. 취합자 임대: 생존 신호의 '취합 가능·순위'를 보고 정합니다 (순위: CPU 마스터 3 > 30번 셀 2 > GPU 0).
7. `jobs/ARBITER.json`에 회차·시각·처리 수를 적습니다.

심판 자격:

- 마스터는 켜지면 `jobs/arbiter_ask/<S>.json`을 씁니다. Apps Script(U2)가 1분마다 보고, LockService 안에서 살아 있는 심판이 없을 때만 `jobs/ARBITER_GRANT.json`(세션·gen)을 씁니다. 자격 판정은 마스터가 켜지거나 바뀔 때만 일어나므로 Apps Script 한도에 부담이 적습니다.
- 마스터는 자격(gen)을 확인한 뒤에만 심판 줄을 시작하고, 매 회 시작에 자격 gen이 그대로인지 확인합니다. 다르면 심판 줄을 멈춥니다.
- 심판이 다시 켜질 때 필요한 상태는 모두 Drive(`assign/`, `locks/`, gen)에 있으므로 새 세션이 이어서 판정합니다.

## 처리 단위

| 단위 | 크기 | 정하는 것 |
| --- | --- | --- |
| 추론 배치 | 프레임 몇십 장 (지금 값) | GPU 효율. CVAT에는 쓰지 않음 |
| TASK | 1개 | 확정·잠금·결과의 단위 |
| 차례 묶음 | **5개 TASK** (`W_CHUNK_TASKS = 5`) 또는 30분(`W_CHUNK_MIN = 30`) 중 먼저 닿는 쪽 | 공정 차례, 잠금 범위, 끼어들기 |

- 묶음이 끝나면 남은 TASK의 잠금을 반납합니다. 다른 사람 요청이 기다리면 차례를 넘기고, 없으면 다음 묶음을 바로 신청합니다.
- 차례를 넘긴 동안 요청은 '진행 중 · 다음 차례 대기 (5/100)'로 보이고, 같은 세션에 배정된 채 남습니다.

## 차례와 순서

- 자원마다 대기열이 있고, 순서는 접수 시각입니다. LC·AA 두 요청 폴더와 사람이 직접 낸 잠금 신청을 하나의 순서로 합칩니다 (D8).
- 여러 TASK 요청은 묶음 5개를 정할 때, 앞 순서의 요청이 기다리는 TASK는 건너뛰고 다음 TASK로 묶음을 채웁니다. 건너뛴 TASK는 그 요청의 뒤 묶음으로 미룹니다.
- 재배정·차례 넘김·격리 뒤에도 요청은 처음 접수 시각으로 순서를 유지합니다.
- 공정 차례(사람마다 돌아가며)는 GPU·입출력 줄을 배정할 때 쓰고, 같은 자원 안의 순서는 접수 시각을 따릅니다.

- 이름·라벨·백업은 허가를 기다린 뒤 다시 읽어 검사합니다. 기다리는 사이 바뀌었을 수 있기 때문입니다.

## 신호 파일

- 신호는 매번 새 이름으로 만듭니다: `jobs/signals/<종류>__<생산자 S>__<순번>.json`. 같은 이름을 다시 쓰지 않습니다.
- 소비자는 처리했다는 표시를 따로 씁니다: `jobs/acks/<소비자 S>__<신호 이름>`. 생산자 파일은 고치지 않습니다.
- 정지처럼 '지금 상태'가 필요한 신호는 같은 종류의 가장 최근 신호(정지 또는 해제)가 지금 상태입니다.
- 마스터·앱·Apps Script가 지금 쓰는 `STOP_MASTER.json`·`STOP_GPU.json`·`STOP_MASTER_released.json`은 이 방식으로 바꿉니다.

## 요청 생성과 실행 설정

- 요청을 만드는 곳은 앱, 수집기, 노트북(라벨 교체 뒤 자동 백업, `new_request`) 셋입니다. 요청 ID는 `<만든 곳>_<S 또는 계정>_<순번>`으로 겹치지 않게 합니다.
- 배정기가 지금 요청 파일에 넣는 기본값(백업의 `export_reviewed=True` 등)은 심판이 `assign/`의 '실행 설정'에 넣습니다. 작업자는 요청 원문의 설정을 먼저 쓰고, 원문에 없는 값만 실행 설정에서 가져옵니다.
- 야간 승인은 사람이 앱에서 승인 신호를 내고 심판이 반영합니다. Apps Script가 배정 파일을 직접 고치지 않습니다.

## 운영 전환

- `config/min_version.json`에 최소 버전을 적습니다. 모든 세션은 생존 신호에 버전을 적고, 최소 버전보다 낮으면 공유 파일을 쓰지 않고 읽기·로컬 준비만 합니다.
- 심판은 최소 버전보다 낮은 세션에 배정·허가를 주지 않습니다.
- 전환 순서: ① 모든 작업자·마스터 멈춤 ② scripts·노트북·Apps Script 반영 ③ `min_version` 올림 ④ 마스터(심판) 켬 — 옛 세션이 받아 둔 요청은 재배정 ⑤ 작업자 켬.
- 개발은 두 번에 나눠도(아래 고칠 곳) 운영 반영은 이 순서로 한 번에 합니다 (D10).

## 계정 역할

| 계정 | 프로젝트 | 하는 일 | CVAT 토큰 | 주기 |
