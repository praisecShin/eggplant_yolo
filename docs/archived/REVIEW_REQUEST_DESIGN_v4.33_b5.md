# v4.33 설계 5판 검토 요청 — 네 관점 검토

`docs/DESIGN_v4.33.md`가 5판으로 바뀌었습니다. 4판 검토 결과(H1~H7)는 `docs/REVIEW_RESULT_v4.33_b4.md`, 그 전 검토는 `docs/REVIEW_RESULT_b1.md`·`docs/REVIEW_RESULT_b2.md`에 있습니다. 구현 때 바꿀 목록은 `docs/IMPL_CHECKLIST_v4.33.md`입니다.

이번에는 바뀐 부분만이 아니라 **시스템 전체를 네 관점에서** 봐 주세요: 동시성 제어, 작업 스케줄링, 장애 복구, 접근 제어. 설계서·점검표·v4.32.0 코드를 함께 대조합니다.

**코드·노트북·시험·설계서는 고치지 마세요.** 결과는 `docs/REVIEW_RESULT_v4.33_b5.md`에 써 주세요. 새 발견은 J1부터 번호를 붙이고, 각 발견에 관점(동시성·스케줄링·복구·접근)을 적어 주세요.

## 시스템 요약 (검토 기준)

- 사람(M)은 분석만 하고, CVAT와 공유 파일을 바꾸는 일은 배정받은 실행기만 합니다.
- 공유 저장소는 Google Drive입니다. 비교 후 쓰기(CAS)가 없으므로 단일 심판(CPU 마스터 판정 루프) + epoch·gen·decision ID로 통제합니다.
- CVAT는 쓰기 펜싱을 지원하지 않습니다. 그래서 옛 실행기의 늦은 쓰기는 막기와 찾아내기를 함께 씁니다(5판 H1). 이 한계 자체는 알려진 제약으로 보고, **그 위에서 남는 위험이 설계에 정직하게 드러나 있는지**를 봐 주세요.
- 심판 자격과 깨우기는 Apps Script Keeper(U2)가 맡습니다.

## 1. 동시성 제어

1. 같은 TASK, 같은 공유 파일, 같은 모델·데이터셋을 두 주체가 동시에 바꿀 수 있는 경로가 남는지 봐 주세요. 대상은 실행기, 심판, 취합 일, 관리 일, 수집기, Keeper, ULD앱, 사람의 분석 세션입니다. '공유 파일별 쓰는 주체' 표와 실제 코드의 쓰기 호출을 대조해 주세요.
2. epoch·gen·decision ID·식별 묶음으로 낡은 판정·보고를 거절하는 규칙이 모든 판정 파일과 보고에 빠짐없이 적용되는지 봐 주세요.
3. 남는 경합이 있다면, 필요한 조건(타이밍·장애 조합)과 영향, '알려진 한계'로 받아들일 만한지 구분해 주세요.

## 2. 작업 스케줄링

1. 차례 규칙(TASK 접수 순서, 사람별 묶음 5개, 30분 부드러운 경계, 받는 중 예외, 관리 일 하나·들어온 순서)으로 굶주림, 교착, 우선순위 역전이 생기는 경우가 있는지 봐 주세요.
2. 관리 일 하나(특히 긴 학습)가 다른 일을 얼마나 막는지, Colab 전용 관리 일(23번)이 실행기 부재로 대기열을 막지 않는지 봐 주세요.
3. 실행기 종류(Colab·GPU·CPU 작업 프로세스)와 일의 종류를 맞추는 규칙(routing, 실행 환경 지정)에 빈틈이 있는지 봐 주세요.
4. 마스터가 꺼져 있을 때 일이 얼마나 지연되는지, 깨우기 조건과 주간 상시 규칙으로 '할 일이 있는데 아무도 깨우지 않는' 경우가 남는지 봐 주세요.

## 3. 장애 복구

1. 판정 루프·마스터·작업 프로세스·실행기·수집기·Keeper 각각이 아무 시점에서나 멈췄다가 다시 시작할 때, 감시·재시작 점검·정기 점검으로 알아채지 못하거나 잘못 복구하는 경우가 남는지 봐 주세요.
2. 복구 자료 게시, 단계 기록, 신호 계획(계획·효과·완료), 관리 일 임시 게시와 확정이 '중간에 끊긴 뒤 다시 하기'에 대해 같은 결과를 보장하는지 봐 주세요.
3. 사람이 고르는 '확인 필요' 흐름(선택 조건, 관리자 강제 해제, 찾아내기)이 사람에게 판단할 충분한 자료를 주는지, 잘못 고를 때의 피해가 제한되는지 봐 주세요.
4. 복구 자료·단계 기록·제출본 보존 기간(30일 등)과 청소가 복구에 필요한 자료를 먼저 지울 수 있는지 봐 주세요.

## 4. 접근 제어

1. 분석 모드(실행 컨텍스트, CVAT 접속 factory 허용 목록, 입력/출력 분리, 좁은 예외 API)가 사람 세션의 쓰기를 실제로 막는 구조인지 봐 주세요. 점검표 A·B의 목록이 v4.32.0의 쓰기 경로를 빠짐없이 덮는지 확인해 주세요.
2. 권한의 근거를 봐 주세요: `people.json`의 역할·권한, Drive 소유 계정, 관리자 계정 2단계 인증. 우회하거나 권한을 넓힐 경로가 있는지, 권한 회수(사람 `stopped`)가 늦게 반영될 때의 영향이 어떤지 봐 주세요.
3. 비밀 값의 위치를 봐 주세요: Colab·Kaggle 보안 비밀, U1 CVAT 토큰, U2 Kaggle 키·`MASTER_NB_SHA256`. 비밀이 코드·Drive·로그·요청·작업 파일로 새는 경로가 있는지, `deploy/` 신뢰 경계로 Keeper의 Kaggle 실행이 보호되는지 봐 주세요.
4. 관리자 동작('보류 해제하고 깨우기', 관리자 강제 해제, `config/*` 수정)이 관리자만 할 수 있는지 봐 주세요.

## 5. 이전 지적의 반영

H1~H7이 5판 '검토 반영표'대로 반영됐는지 해결·부분 해결·미해결로 짧게 판정해 주세요. TOTP를 넣지 않기로 한 것은 결정이므로 결함으로 세지 않아도 됩니다.
