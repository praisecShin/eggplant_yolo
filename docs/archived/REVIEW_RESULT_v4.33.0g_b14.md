## 검토 질문별 추가 판단

- **검증 사슬:** 생성기는 manifest 해시를 뿌리 노트북에 고정하고 Keeper용 노트북 해시를 출력한다. manifest·파일 동시 변조도 고정 해시에서 차단하는 공식 시험이 통과했다. 목록 안의 모듈은 검증 바이트로 실행하고 기존 동명 sys.modules 항목을 지운다. 다만 목록 밖 의존성은 U2다. 외부 패키지·도구 설치는 별도 신뢰 기반이며 이 해시 사슬에 포함되지 않는다.
- **작업 프로세스 코드:** write_code_dir은 검증한 scripts 바이트를 새 0700 폴더에 쓰고 `python -I`에 그 폴더를 넘긴다. 실제 작업 프로세스 기동·멈춤 시험도 통과했다. -I는 작업 디렉터리·사용자 경로 혼입을 줄이지만, 승인된 외부 의존성 정책까지 대신하지 않는다.
- **시험·운영 분리:** 생성된 뿌리의 TEST·remote와 GPU -test 주소 확인은 정상 생성 묶음의 혼동을 줄인다. 그러나 `check_remotes`는 이름에 test가 포함되는지만 보며 remote의 root_folder_id는 확인하지 않는다. 시험 이름 연결이 운영 폴더를 가리키면 통과한다. 이는 문서에 공개된 이름 기반·관리자 설정 신뢰 범위로 받아들일 수 있으나, 예행 연습 전 실제 폴더 ID 대조가 필요하다. 임의 GPU 노트북의 내부 운영 경로를 -test slug가 바꿔 주지는 않는다. 2b의 시험 프로젝트·REH_ TASK 강제를 완료하기 전에는 이 묶음을 안전한 실작업 예행 연습 도구로 보아서는 안 된다.
- **비밀 값:** 여러 연결의 한 줄 rclone 설정 복원, 세션 전용 임시 경로, 처음부터 0600으로 여는 비밀 파일, CVAT_TOKEN의 프로세스 환경 전달을 추적했다. 지정한 정상 경로에서 공유 파일·마스터 로그로 비밀을 쓰는 경로는 찾지 못했다. Kaggle 응답 원문을 GPU 실패 기록에 넣지 않는 것도 확인했다. 모든 설정 변형·외부 라이브러리 예외 출력을 전수 검증한 것은 아니다.
- **자격 상실 뒤 10분:** 옛 마스터가 작업 프로세스를 즉시 끄지 않는 것 자체를 결함으로 보지는 않는다. 자격을 잃은 MasterLoop는 배정하지 않고, Executor는 현재 grant·epoch·잠금을 확인해야 한다. 새 epoch의 인계도 같은 세션을 다룬다. 이 평가는 2b의 모든 실제 쓰기가 해당 권한 검사를 통과한다는 조건이다. 진행 중 외부 호출의 종료는 별도 확인해야 한다.
- **종료 순서:** 멈춤 파일을 먼저 쓰고 최대 2분 기다린 뒤 terminate, 그 다음 마스터 Beat를 종료하는 순서는 정상 시험에서 맞다. 다만 terminate 뒤 실제 종료를 wait/kill로 확인하지는 않는다. SIGTERM을 무시하는 처리기까지 강제 종료된다는 보장은 없으므로 2b에서 종료 시간 한도·진행 감시와 함께 확인해야 한다.
- **유휴·GPU 요약:** gpu_needed는 해당 route를 수행할 살아 있는 실행기가 없을 때 계산한다. cpu로도 수행 가능한 일은 cpu가 있으면 GPU가 필요 없다는 판정이 맞다. busy는 실행형 needs_check도 포함하므로 사람이 풀지 않는 관리·학습 일은 밤에도 마스터를 실행 한도까지 유지할 수 있다. ‘사람 확인 대기’를 유휴로 볼지는 정책을 명확히 할 필요가 있다.

## 2b 전 최소 수정 목록

1. **U1:** 보고의 복합 필드까지 검사하고 잘못된 파일 하나가 다른 요청 진행을 막지 않게 한다.
2. **U2:** 배포 모듈의 import 경계를 닫고, 목록 누락·사전 로드·디스크 동명 반례를 시험한다.
3. **U3~U5:** 바깥 조회의 상태 필드·최신성·응답 형태를 확인하며, 실패와 불명 응답을 일관되게 모름으로 전달한다.
4. **예행 연습 전 U6·U7:** 불완전 관측으로 유휴 종료하거나 GPU 재기동을 확정하지 않게 한다.
5. 기존 2b 필수 조건인 쓰기 직전 권한 검사·백업·사람 라벨 보호·진행 감시·서버 시간 한도·최종 산출물 검증·시험 TASK 범위 강제를 실제 처리기에 붙인다. 현재 no_handler 실패는 문서에 밝힌 미구현 사항이므로 별도 발견으로 세지 않았다.

## 점검했지만 문제가 없던 항목

- 지정 시험 439개와 b13 숫자 name 재현의 해소.
- S2의 실제 옛 배정 경로와 S3의 운영 비조작 단계 대응표.
- Keeper·심판의 사람 active 상태 해석 일치.
- manifest 고정 해시·파일별 해시, 목록 안 모듈의 검증 바이트 사용.
- GPU 노트북·실행 설정이 검증 파일 사전에서 선택되고 시험 주소가 확인되는 정상 경로.
- CPU 작업 프로세스의 전용 코드 폴더, 격리 실행, 새 세션 재시작과 재시작 횟수 제한.
- 정상 종료에서 작업 프로세스 멈춤 요청이 마스터 최종 생존 신호보다 앞서는 순서.
- 최소 버전 파일이 없거나 버전이 낮을 때 자격 신청·heartbeat 전에 거절하는 정상 형식 경로.

## 시간이 모자라 보지 못한 항목·한계

- 기존 v4.32 전체 회귀 시험, 모든 입력 필드 퍼징, 모든 파일 쓰기 중단 조합은 실행하지 않았다.
- 실제 CVAT API 스키마·페이지 동작, Kaggle CLI 출력·중복 실행 정책, Drive 소유자·지연·권한은 확인하지 않았다. 이는 실제 서비스 접속 금지 지침에 따른 범위 제한이다.
- 2b 처리기·새 GPU 노트북·시험 TASK 강제·2f 전환 도구는 미구현이므로 운영 효과까지 검증하지 못했다.
- 신뢰된 관리자 자체의 악의적인 manifest, 설치 도구·외부 패키지 공급망, 모든 secret 설정 오류 조합은 이번 검토에서 전수 분석하지 않았다.
