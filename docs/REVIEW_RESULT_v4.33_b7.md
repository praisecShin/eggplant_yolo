### L3 — 잠금 밖 ULD의 빈 TASK를 우리 생성 결과로 오인할 수 있음

| 칸 | 내용 |
|---|---|
| 번호 | L3 |
| 심각도 | 높음 |

## 3. 계정 사실·관리자 폴더·보조 실행기 대조

- **계정 역할:** A0 사람/앱/Colab/보조 Kaggle, K 마스터/CPU/GPU, G 수집기/Keeper의 지도는 요청서 사실과 일치한다. K의 RCLONE_CONF가 K 인증이어야 한다는 조건도 맞다. G가 K Kaggle 키로 마스터를 push해도 Drive 자격은 K 노트북의 K 인증을 쓰므로 판정 파일 계정이 G가 되는 구조는 아니다.
- **시스템 입력:** K 복구 요청, G 자동 요청, G가 원관리자 신호를 연결하는 해제 신호를 허용 입력으로 구분해 b6의 정상 시스템 입력 거절 문제를 다룬다. 접수 기록의 시스템 요청자는 people의 사람 등록과 별도 역할로 처리하는 시험이 필요하다.
- **요청자 유지:** v4.32.0은 `web_bridge.set_status`(341~356행)에서 상태 이름의 새 파일을 만들고, CPU 마스터 `push_req`(686~701행)에서 그 파일을 게시한다. 이때 원요청자를 현재 파일 소유자로 다시 정하지 않고 K 심판의 intake를 따르는 방향은 적절하다. intake도 K 소유·현재 epoch의 심판이 쓴 기록인지 확인해야 한다.
- **관리자 전용 폴더:** 공유 폴더 밖 별도 루트로 deploy와 정책 config를 옮기는 설계는 K/G의 공유 편집 권한과 관리자 설정 편집 권한을 분리한다. config의 동적 시험 상태는 L1로 구분했다. 코드/앱은 정책 루트와 데이터 루트의 같은 이름 파일을 혼동하거나 옛 공유 config로 자동 fallback하면 안 된다.
- **A0 Kaggle 보조 실행기:** 같은 배정·잠금 규칙을 사용하고 마스터 역할을 주지 않으므로 보조 계정이 생겼다는 이유만으로 두 심판이 필요하지 않다. A0 Kaggle에는 A0 Drive 인증과 공통 CVAT 토큰만 요구하므로 K Kaggle 키를 복사할 필요도 없다. 실행 환경(Colab/Kaggle)과 소유 계정(A0/K)을 별도 속성으로 둬 A0 Kaggle을 Colab 전용 23번에 배정하지 않아야 한다. 사람이 켠 A0 세션 등장으로 비켜 둔 학습이 깨는 경로는 495행에 있다.
- **CVAT 단일 계정:** 만든 사용자만으로 ULD·사람·실행기를 구별할 수 없다는 새 설명은 정직하다. 기존 16번은 create_from_backup, 17번은 create_from_data 한 호출 뒤에 새 번호를 받는다. 빈 TASK 먼저/미디어 분리 절차가 현재 SDK/서버에서 가능한지는 요청서 범위 밖의 실측 항목이며, 특히 백업 복원을 기존 빈 TASK에 이어갈 수 있는지는 별도 확인해야 한다. 불가능하면 승인 없는 다른 경로로 우회하지 말고 그 작업은 보수적인 확인 필요 복구를 유지한다.

## 4. 새 규칙의 잔여 위험과 구현 시험

### 접수 기록

새 intake는 원요청자·공정 차례의 기준이면서 cancel_signal의 저장소다. 심판 단일 작성자 원칙으로 방향은 맞다. 다음을 시험에 넣는다.

- intake가 없거나 읽을 수 없으면 실행하지 않음. 최초 접수 파일과 상태 재게시를 구분하고 요청 ID가 충돌하면 다른 요청의 intake를 재사용하지 않음.
- intake에 최초 권한 판정을 남기는 것과 **지금 people의 active/권한 확인**을 구분함. 이미 실행 컨텍스트를 받은 일의 유지 결정은 기존 한계대로 따르되, 단지 접수된 대기 요청을 영구적인 실행 권한으로 해석하지 않음.
- A0 생성→K 처리→A0 보조 실행기로 재배정 뒤에도 원요청자 유지. G 자동 요청·K 복구 요청도 정상 접수.
- intake에 cancel_signal을 쓴 뒤 요청 상태/요약 반영 전에 종료해도 취소가 유지됨. 옛 심판 재게시로 취소 표시가 사라지면 현재 심판이 최신 상태로 복원함.

### 효과별 완료 증거

K1의 두 반례는 새 규칙으로 닫힌다. 다만 모든 효과가 같은 by_signal 하나를 공유하지 않게 **효과별** 증거를 확인해야 한다. 잠금 전이와 복구 요청 생성의 증거를 따로 대조하고, 재발급이 by_signal을 누락하거나 다른 신호가 그 필드를 바꾼 경우도 안전하게 재판정해야 한다. gen 불일치만으로 성공 완료하거나 옛 JSON을 복원하는 구현은 새 설계를 따르지 않는다.

‘취소됨’ 표시는 TASK 시작 전 확인 외에 기존 약속인 준비 단계 중단·확정 신청 후 TASK 마무리 경계와 연결한다. 목록을 이미 받은 병렬 줄도 자기 TASK 시작 때 같은 intake를 다시 확인한다. 요청이 이미 완료돼 무효화된 효과와 실제 취소된 효과를 결과에서 구분한다.

### locks/create

생성 잠금 키는 이름 해시만 같다고 충돌/공유시키지 말고 서버·CVAT 계정·정규화한 이름의 자원 ID를 일관되게 만들어야 한다. 빈 TASK 응답 유실 중에는 뒤의 동명 요청을 열지 않고 확인 필요/예약 상태를 유지한다. 늦게 돌아온 옛 실행기의 create 자체는 CVAT 펜싱 부재의 영향을 받으므로 의도/작업 번호를 보존한다. L3의 잠금 밖 빈 후보도 시험에 포함한다.

### 배포 검증

새 한 방향 사슬은 정상 배포를 만들 수 있다. `/tmp/egg_b7_probes.py`의 파일 해시→manifest→루트 노트북→Keeper 해시 모형에서 검증이 통과했다. 실제 구현은 검증한 바이트를 import/load_script/subprocess/_lc_run에 넘기며, GPU 노트북 기동도 기존 CPU 마스터 532~557행의 공유 notebooks 최신 선택을 그대로 쓰지 않아야 한다. 점검표 147행이 이 지점을 명시했다.

GPU 노트북이 배포 목록에 포함되는 만큼 그 GPU 노트북에 **같은 목록 해시를 다시 내장하는 순환**을 만들지 않는지도 확인한다. 상위의 검증된 마스터가 검증한 목록/파일을 자식에게 전달하거나 별도 계층으로 검증한다. 사람이 켜는 A0 Kaggle 사본의 신뢰 시작점은 승인된 사본/목록 해시로 고정하고 변조된 파일은 실행 전에 거절한다.

### 시험 설정 변경

결정 가의 계속 학습·새 기준 오염 표시·평가 제외는 수용된 정책이다. 새 시험 버전 채택과 모델 완료 보고가 같은 회차에 들어오는 순서를 바꿔도 최종 오염/채택 결과가 같아야 한다. 오염 여부는 모델 이름 전체의 영구 플래그가 아니라 **모델 버전·시험 설정 버전**에 대응해야 한다.

이미 만든 D0에 X가 들어 있는데 T1에서 X가 시험이 된 뒤 **새 모델을 D0로 시작**하는 경우도 시험한다. T1 채택 때 아직 모델이 없으면 기존 모델 대조만으로는 걸리지 않으므로, 230행의 시작 시점 약속을 데이터셋 출처로 재검증한다. legacy 모델/데이터셋에 출처가 없으면 ‘겹치지 않음’으로 처리하지 말고 평가 호환을 확인할 수 없는 상태로 둔다. 기존 15번 194~206행의 제외와 `cvat_task_tools.test_key`(2535행 이후)의 그루·촬영일 묶음을 유지한다.

## 5. 추가된 알려진 한계 판정

7판 표에서 관련되는 추가 항목은 다음과 같다. 항목 수의 표현보다 실제 조건을 기준으로 판정했다.

| 항목 | 판정 |
|---|---|
| Keeper 재시도 중복 기동(591행) | 정직하게 명시했다. 남는 프로세스가 자격 확인 전에 공유 쓰기/작업 배정을 하지 않는 시험이 필요하다. 자격을 못 받은 마스터가 K 소유라는 이유만으로 판정할 수는 없다. |

## 6. 구현 1단계에 전달할 최소 보완

1. **L1:** admin 정책 루트와 K가 쓰는 시험 설정 상태 루트를 확정하고 경로·작성자·전환 계정을 맞춘다.
2. **L3:** 잠금 밖 빈 후보는 자기 생성의 증거 없이는 자동 인계하지 않는다.
3. **L2:** 소유자 필터를 생성 계정 확인으로만 쓸지, 내용 작성자까지 인증할지 신뢰 범위를 문서에 명시한다. 모든 공유 편집자를 신뢰하는 운영을 선택할 수 있으며, 이 경우 별도 보안 장치를 필수 요구로 늘릴 필요는 없다.

판정 함수·가짜 환경 시험은 계속 구현할 수 있다. 새 테스트에는 K1의 두 반례, K4의 미래 시각/목록 관측 틈, L1의 읽기 전용 admin 경로, L3의 ULD 빈 후보, A0/K/G 교차 상태 변경을 먼저 넣는 것이 적절하다.

## 점검했지만 문제가 없던 항목

- 신호: gen만 보고 완료하지 않고 논리 대상과 효과별 증거를 대조하며 취소를 요청에 붙인다.
- 배포: 루트 노트북/목록 자신을 제외한 순서로 정상 배포를 만들 수 있고 GPU·동적 로딩·subprocess까지 검사 대상으로 포함했다.
- 신원: 실제 A0/K/G 지도, G 해제 신호의 원관리자 재확인, 최초 요청자 intake 보존, 사람 추가 전 앱 계정 전환 조건이 명시됐다.
- 스케줄링: next_wake_at·미관측 요청 ID·새 실행기 등장으로 b6의 깨우기 반례를 다룬다. A0 보조 Kaggle은 심판 역할 없이 기존 배정에 참여한다.
- 학습: 결정 가에 따라 출처를 고정하고 새 시험 기준 오염 모델을 평가·비교에서 제외하며 채택 대기로 둔다.

## 시간이 모자라 보지 못한 항목 및 검증 한계

- 요청된 K1~K6·계정 사실·새 규칙은 모두 검토했다. 변경 없는 절과 이전 전체 코드 점검을 다시 수행하지 않았다.
- `/tmp/egg_b7_probes.py`에서 외부 접속 없이 비순환 배포 성공, intake 취소의 gen4 인계 유지, ULD 빈 후보의 자동 인정, T1 이후 D0 신규 학습의 충돌을 모형으로 확인했다. 이는 새 v4.33 구현 시험이 아니다.
- v4.32.0의 상태 새 이름 게시, 기존 파일 내용 갱신, GPU 노트북 선택·기동, 15번 시험 제외·학습 출처, 16/17번 생성 호출을 읽었다. 실제 새 API가 빈 TASK/백업 복원을 지원하는지는 실측하지 않았다.

- 저장소 밖 앱·ULD 구현과 F7·F8은 보지 않았다. 새 판정/계정 처리 구현이 없어 새 행동 시험이나 기존 회귀 시험을 실행하지 않았다.
