## 7. ULD앱 임시 규칙 (ULD앱 새 판까지)

ULD앱을 기다리지 않고 나머지를 먼저 전환합니다 (결정, 11/14).

- ULD앱의 **새 TASK 올리기**는 그대로 씁니다. 수집기가 새 `_uld` TASK를 보고 백업 요청을 만듭니다.
- ULD앱의 **기존 TASK 교체**(옛 TASK를 지우고 새로 올림)는 **보류**합니다 (R5). 정지를 건 것만으로는 그 TASK에 실행기가 쓰고 있지 않다는 증거가 되지 않습니다. 정지는 이미 승인된 확정 단계를 끝까지 마치게 하고, 이미 보낸 CVAT 가져오기를 멈추지 않기 때문입니다.
- 급하게 교체해야 하면 관리자가 손으로 합니다. 아래 확인 중 하나라도 '모름'이면 교체하지 않습니다.
  1. CTRL앱에서 정지를 겁니다.
  2. CTRL앱에서 그 TASK의 잠금이 비어 있고, '확인 필요'가 아니고, 배정된 요청이 없음을 확인합니다.
  3. CVAT에서 그 TASK의 진행 중 가져오기 작업이 없음을 확인합니다.
  4. 교체합니다.
  5. 해제합니다.
- 심판은 ULD가 만든 이름 같은 빈 TASK를 이어받지 않고 '확인 필요'로 둡니다 (설계 L3).

시험 TASK 범위: 시험 수집기·심판·실행기는 `eggplant_AA` 프로젝트이면서 이름이 `REH_`로 시작하는 TASK만 다룹니다. 요청에 TASK 번호를 직접 적어도 이 범위 밖이면 거절합니다 (2단계 구현, 시험 설정에서만 켬).

## 9-1. 관리자 복구 절차 (보호 모드)

보호 모드 메일·푸시가 오면 이 순서로 합니다.

1. CTRL앱 위쪽 띠 또는 메일에서 **손상된 파일 경로와 이유**를 봅니다 (`arb/ARBITER.json`의 `protect`).
2. 그 파일이 가리키는 일을 확인합니다. 배정·잠금이면 해당 실행기의 생존 신호와 단계 기록(`recovery/`), CVAT의 TASK 상태·진행 중 가져오기를 봅니다.
3. 파일을 바로잡습니다.
   - 사람이 실수로 고친 것이면: Drive 버전 기록에서 직전 판으로 되돌립니다. 판정 파일은 심판만 쓰므로 직전 판이 마지막 정상 상태입니다.
   - 되돌릴 판이 없으면: 2번에서 확인한 실제 상태에 맞게 칸을 채웁니다. `by_session`·`by_epoch`는 지금 심판의 값(`arb/ARBITER.json`의 `session`·`epoch`)으로 적습니다.
   - **파일을 지우지 않습니다.** 지우면 '없음'이 되어 같은 TASK가 다시 배정될 수 있습니다.
4. 다음 회차(25초 안)에 보호 모드가 풀리고 '보호 모드 끝남' 메일·푸시가 옵니다.

예행 연습(8절)에서 이 절차를 한 번 해 봅니다: 시험 폴더의 보류 파일 하나를 일부러 망가뜨리고 → 알림 → 되돌리기 → 끝남 알림.

## 9-2. 옛 모듈 이름 규칙

`dev_tools/build_deploy.py`의 `LEGACY_MODULES`에는 scripts에서 **지우거나 이름을 바꾼 모듈 이름을 계속 쌓습니다** (지우지 않음). 뿌리 노트북은 이 이름들을 배포 목록에 없으면 어디서도 불러오지 않습니다 (b16 W3).
