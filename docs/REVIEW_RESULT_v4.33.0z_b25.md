## 새 발견

### F1 — 학습 묶음의 리더가 먼저 끝나면 손자 프로세스를 남긴다

| 칸 | 내용 |
| --- | --- |
| 번호 | F1 (요청서 확인 전 임시 번호) |
| 심각도 | 높음 |
| 관련 항목 | b24 T4, DESIGN 0z의 학습 묶음 전체 종료 약속, 새 발견 |
| 위치 | `drive/scripts/h_run.py:187` RealTrainer.train의 리더 종료 분기, `:197` 실패 처리, `:205` RealTrainer._kill |
| 무엇이 문제인가 | 종료 완료 여부를 프로세스 묶음 전체가 아니라 Popen으로 띄운 리더의 poll 결과만으로 판단한다. TERM 뒤 리더가 종료되면 TERM을 무시하는 손자가 남아도 KILL을 보내지 않는다. 리더가 먼저 비정상 종료한 경로도 _kill을 거치지 않는다. 권한 상실/실패를 보고하고 돌아온 뒤에도 DDP 하위 프로세스가 계속 GPU·작업 폴더를 사용할 수 있다. |
| 일어나는 조건 | `rLog/b25_process_probe.py`에서 실제 RealTrainer가 띄운 로컬 자식 아래에 TERM을 무시하는 손자를 만들었다. ① 권한 상실로 AuthorityLost를 낸 경우, ② 리더가 스스로 종료 코드 3으로 끝나 RuntimeError를 낸 경우 모두 train 반환 뒤 손자가 살아 있었다. 재현에서 생성한 잔여 프로세스는 finally에서 직접 KILL로 정리했다. |
| 확신 | 확인함 — 실제 Popen·프로세스 그룹·신호를 사용한 로컬 재현. 실제 GPU/DDP 실행은 아님. |
| 제안 | 리더 상태와 별개로 해당 프로세스 그룹의 잔존 여부를 확인하고 유예 뒤 그룹 전체에 KILL을 보낸다. 리더 비정상 종료·부모 예외·권한 상실 모두 같은 정리 절차로 보낸다. 리더 종료만으로 그룹 종료를 판정하지 않는 회귀를 추가한다. |
| 2c로 넘어가기 전 필수 여부 | 필수. 별도 학습 프로세스의 권한 상실 시 전체 종료를 보장한 것으로 셀에 연결하기 전에 해결해야 한다. |

공식 손자 종료 시험은 손자가 기본 TERM 동작을 따르는 경우만 확인하므로 통과한다. 추가 재현 결과는 `b25_process_probe.log`의 두 행 모두 grandchild_alive_after_return=true다.

| 칸 | 내용 |

| 무엇이 문제인가 | files를 구할 때는 man이 dict인지 확인하지만 다음 조건에서 man.get을 무조건 호출한다. CURRENT가 가리키는 _files.json이 []나 null이면 AttributeError가 발생해 정상 모델까지 포함한 전체 목록 계산·refresh가 실패한다. ‘확인 안 된 버전은 빼고 넘어감’이라는 함수 계약과 다르다. |

| 제안 | manifest 및 필요한 하위 파일 정보의 형태를 먼저 확인하고 불완전한 모델만 제외한다. 제외 사유·개수를 상태에 남길 수 있다. 정상 모델과 잘못된 모델이 함께 있는 회귀를 추가한다. |
| 2c로 넘어가기 전 필수 여부 | 필수 아님. 모델 선택·취합의 오류 격리를 마치기 전 보완할 사항이다. |
